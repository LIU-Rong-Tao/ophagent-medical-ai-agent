# v0.6.0 Report Generation Design

## 0. 研究问题与贡献

### 研究问题

在缺乏眼底图像-医生报告配对数据、病灶级标注以及多模态临床上下文的受限数据条件下，如何构建一个可审计、可升级的眼科病例报告工作流，同时不允许产生无依据的医学结论？

### 研究假设

证据瓶颈设计可以使报告草稿比单纯的模板生成或自由生成更可控、可审计、可追踪、可升级，因为报告中的每一句结论都必须基于结构化的模型预测、弱视觉证据、质量上下文和明确的局限性声明。

### v0.6.0 的贡献

1. 为数据受限的眼科病例报告原型定义了一个证据瓶颈结构化规范。
2. 实现了一个从模型预测到报告生成的可复现单图病例构件流水线。
3. 在报告渲染中引入了质量感知提示和非临床使用的安全约束。
4. 建立了报告结论与结构化证据之间的结论级可追溯机制。
5. 提供了一个轻量级验证模块，用于检查规范合法性、安全声明覆盖度、无依据结论检测以及证据覆盖情况。
6. 提供了一个可替换架构，支持未来将 CAM 替换为病灶分割/检测、将模板报告替换为 LLM 生成、将静态质量提示替换为自动质量评估模型。

## 1. Version Positioning

v0.6.0 的目标是把 OphAgent 从 benchmark / CAM demo 进一步收敛为一个可展示、可复现、可升级的眼科病例分析报告原型。

本版本不训练端到端医学报告生成模型，也不声称实现临床级 ophthalmic report generation。

v0.6.0 的核心定位是：

Evidence-Bottleneck Case Report Prototype

也就是说，系统不是直接从图像自由生成报告，而是先把模型输出整理成结构化 evidence bottleneck，再由报告渲染模块生成 Markdown / HTML 报告草稿。

当前 pipeline 为：

Fundus Image → Prediction → Weak Visual Evidence → Structured Findings → Quality-aware Context → Report Claims → Validation → Report Draft → Case Artifact

本版本输出不是临床诊断报告，而是用于科研展示、导师沟通、医院需求对接和后续系统升级的 case analysis report draft。

## 2. Design Motivation

当前 OphAgent 已经完成了以下基础能力：

- APTOS2019 DR grading benchmark
- ConvNeXt / Swin / ViT / RETFound 多 backbone 对比
- multi-metric evaluation
- CAM adapter
- selected CAM visualization
- early structured findings / reasoning demo

但现有结果仍然偏向实验和模块验证，缺少一个最终可展示的病例级输出。

v0.6.0 需要解决的问题是：

在缺少眼底图像-医生报告配对数据、病灶级标注和完整临床上下文的条件下，如何构建一个可追踪、可审核、未来可替换升级的眼科病例报告原型？

因此，本版本重点不是报告文本本身，而是报告前面的 evidence control layer。

报告只能引用 structured findings 中已有的证据，不能凭空新增医学判断。

## 4. Stable Design Principles

v0.6.0 从前沿工作中保留的是稳定原则，而不是临时实现细节。

这些原则在未来获得高质量数据后仍然不会被推翻。

### 4.1 Evidence-first Reporting

报告生成应该先有证据，再生成文本。

在 OphAgent 中，证据包括：

- 模型预测结果
- 置信度
- CAM 弱视觉证据
- 结构化 visual findings
- 图像质量上下文
- limitations
- provenance metadata

未来如果获得 lesion mask、bounding box 或 detector output，可以替换当前 CAM evidence，但 evidence-first 的原则不变。

### 4.2 Structured Findings

报告不应直接从模型输出自由生成，而应先经过结构化 findings。

结构化 findings 的作用是：

- 限制报告可引用的信息范围
- 保存中间证据
- 支持人工审核
- 支持后续 LLM / RAG / LoRA 替换
- 支持后续自动评估

### 4.3 Claim-level Traceability

v0.6.0 不只生成报告文本，还需要保存 report claims。

每条 report claim 都应包含：

- claim_id
- text
- claim_type
- supported_by
- safety_level

这样后续可以检查：

- 是否存在没有 evidence 支撑的 claim
- 是否存在 clinical diagnosis claim
- 是否存在把 CAM 误写成 lesion annotation 的 claim
- 是否存在对 image quality 的过度声称
- 是否遗漏 human review required

这一步是后续 LLM / RAG / LoRA 接入的基础。

### 4.4 Localization → Feature → Interpretation

参考 FundusExpert / FundusGen 的认知链思想，报告应避免从分类结果直接跳到诊断结论。

v0.6.0 采用简化认知链：

Weak visual evidence → visual finding → interpretation summary

当前版本只使用 CAM 作为弱视觉参考，不进行真实病灶定位。

### 4.5 Quality-aware Reporting

医学图像质量会直接影响模型输出可靠性，但低质量图像不应该被简单等同于无效输入。

Reti-Pioneer 的质量感知设计说明，在真实临床和基层筛查场景中，图像质量差异本身可以作为模型决策和报告解释的一部分。轻中度质量下降的图像应该触发 caution / uncertainty note，而不是自动拒答。

因此，v0.6.0 不再把 low-quality refusal 作为默认方向，而采用：

quality-aware reporting

当前版本不训练图像质量评估模型，但需要在 case artifact 中记录 image_quality_note，明确当前系统尚未自动评估图像质量。

后续可升级为：

- image quality assessment module
- quality-aware evidence weighting
- quality-aware confidence adjustment
- quality-aware report wording
- low-quality caution rather than automatic refusal
- non-diagnostic image refusal only for extremely unreadable images

### 4.6 Human-review-required Output

所有报告输出均必须声明：

- 不是临床诊断
- 不能替代医生阅片
- CAM 不是病灶标注
- 当前系统未经过临床验证
- 输出需要医生审核

## 5. Current Data-limited Implementation

v0.6.0 的部分实现是数据受限条件下的工程简化，不能包装成前沿论文中的完整方法。

| 当前实现 | 性质 | 未来替换方式 |
|---|---|---|
| CAM 作为 weak visual evidence | 临时简化 | 替换为 lesion segmentation mask / bounding box / detector output |
| 规则化 findings | 临时简化 | 替换为医生验证的 structured findings 或 lesion detector 输出 |
| 模板 report draft | 临时简化 | 替换为 LLM / RAG / LoRA report renderer |
| 静态 image_quality_note | 临时简化 | 替换为 image quality assessment module |
| rule-based validation | 临时简化 | 替换为 LLM-based claim checker / clinical review protocol |
| 不做 supervised report generation | 数据限制 | 有 image-report pairs 后训练 report generator |
| 不做 BLEU / ROUGE / CIDEr | 数据限制 | 有 reference reports 后增加文本指标和医生评分 |
| 不做 RAG | 数据限制 | 有院内指南、模板、病例库后接入 knowledge grounding |

当前版本必须明确：

CAM is weak visual evidence, not lesion annotation.

Template report is a research/demo draft, not a clinical report.

Image quality is not automatically assessed in v0.6.0, and report interpretation should remain cautious.

## 6. Future-upgradable Architecture

v0.6.0 的代码结构应避免写死 CAM、模板报告和简单拒答逻辑，而是预留可替换模块。

推荐抽象为：

- prediction_provider
- evidence_provider
- quality_context_provider
- finding_builder
- claim_builder
- report_renderer
- report_safety_checker
- artifact_writer

当前实现与未来升级关系如下：

| 模块 | v0.6.0 当前实现 | 未来升级 |
|---|---|---|
| prediction_provider | ConvNeXt / current classifier | foundation model / MLLM / multi-task model |
| evidence_provider | CAM overlay | segmentation mask / bbox / lesion detector |
| quality_context_provider | static image_quality_note | trained image quality assessment / quality-aware weighting |
| finding_builder | rule-based schema | doctor-verified findings / detector-based findings |
| claim_builder | rule-based claim list | LLM-generated claims with schema validation |
| report_renderer | template markdown / html | LLM / RAG / LoRA report generator |
| report_safety_checker | rule-based validation | hallucination checker / unsupported claim checker |
| artifact_writer | local case folder | web demo / database / deployment interface |

这样后续拿到高质量数据时，不需要推翻 pipeline，只需要替换 provider。

推荐默认样例：

## 9. findings.json Design

findings.json 是 v0.6.0 的核心，不只是报告附属文件。

它承担 evidence bottleneck 的角色。

建议字段包括：

- case_id
- input
- prediction
- evidence
- findings
- interpretation
- report_claims
- quality_control
- limitations
- model_info
- provenance

### 9.1 prediction

保存模型预测结果：

- prediction_id
- raw_class
- display_name
- confidence
- topk_predictions

### 9.2 evidence

保存证据，不写死 CAM。

evidence_type 可以包括：

- cam
- segmentation_mask
- bounding_box
- lesion_detector
- clinical_metadata
- report_reference

v0.6.0 当前只实现：

- evidence_type: cam
- clinical_strength: weak

每条 evidence 应包含：

- evidence_id
- evidence_type
- source
- region
- description
- clinical_strength
- caution
- replaceable_by

### 9.3 findings

保存结构化视觉线索。

第一版可以包括：

- finding_id
- finding_type
- description
- supported_by
- confidence_level
- caution

但必须避免写成已确认病灶。

### 9.4 interpretation

保存报告摘要所需的可引用解释。

interpretation 只能引用 prediction、evidence、findings 和 quality_control 中已有内容。

### 9.5 report_claims

保存可验证的报告声明。

每条 claim 应包含：

- claim_id
- text
- claim_type
- supported_by
- safety_level

claim_type 可以包括：

- model_prediction
- visual_evidence
- quality_context
- limitation
- disclaimer
- artifact_metadata

report.md 只能渲染 report_claims 中已有的声明，不能新增 unsupported medical claim。

### 9.6 quality_control

quality_control 不应该只表达 refusal。

v0.6.0 推荐字段：

- image_quality_assessed
- image_quality_level
- quality_aware_mode
- quality_note
- action
- future_upgrade

v0.6.0 当前默认：

- image_quality_assessed: false
- image_quality_level: unknown
- quality_aware_mode: not_implemented
- action: caution

action 后续可支持：

- use
- use_with_caution
- refuse_non_diagnostic

### 9.7 limitations

必须包含：

- no lesion-level annotation
- no physician report ground truth
- no multimodal clinical context
- automatic image quality assessment not implemented
- CAM is not lesion localization
- not clinically validated
- not for clinical diagnosis

## 10. validation.json Design

validation.json 是 v0.6.0 的轻量评估与安全检查输出。

它不评估医学正确性，而评估 artifact 是否满足 evidence-bottleneck 和 safety constraints。

建议字段包括：

- schema_valid
- required_files_present
- required_disclaimer_present
- human_review_required
- cam_described_as_weak_evidence
- clinical_diagnosis_claim_present
- unsupported_claim_count
- unsupported_claim_ids
- evidence_coverage_rate
- image_quality_overclaimed
- non_clinical_use_statement_present
- report_reproducible
- validation_warnings

### 10.1 validation goals

v0.6.0 validation 目标：

- 检查 findings.json 是否包含必要字段
- 检查 report_claims 是否都有 supported_by
- 检查 report.md 是否包含 required disclaimer
- 检查 CAM 是否被描述为 weak evidence
- 检查 report 是否出现 clinical diagnosis claim
- 检查是否过度声称 image quality 已被自动评估
- 检查 report 是否只使用 findings.json 中已有 claim

### 10.2 v0.6.0 evaluation metrics

v0.6.0 不使用 BLEU / ROUGE / CIDEr。

当前适合的 evaluation 包括：

- artifact completeness rate
- schema validation pass rate
- unsupported claim count
- required safety statement pass rate
- evidence coverage rate
- CAM wording safety pass rate
- image quality overclaim check
- report reproducibility check

## 11. report.md Design

report.md 是 findings.json 的展示层，不是新的事实来源。

建议 section：

- Case Overview
- Input Image
- Model Prediction
- Confidence and Uncertainty
- Visual Evidence
- Quality-aware Context
- Structured Findings
- Interpretation Summary
- Limitations
- Non-clinical-use Disclaimer
- Artifact Metadata

报告中必须明确：

- This is an AI-generated draft.
- This report is for research and demonstration only.
- The result must not be used for clinical diagnosis or treatment decisions.
- CAM-based evidence is weak and should not be interpreted as lesion annotation.
- Image quality is not automatically assessed in the current version.
- Human review is required.

报告不能写：

- 模型发现了真实病灶
- 病人确诊某疾病
- CAM 精准定位了病灶
- 图像质量已经被自动验证
- 低质量图像一定无效
- 建议临床治疗方案
