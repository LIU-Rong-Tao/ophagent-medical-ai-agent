# v0.6.0 Report Generation Design

## 1. 目标定位

v0.6.0 的目标是把 OphAgent 从 benchmark / CAM demo 进一步收敛为一个可展示、可复现的眼科病例分析报告原型。

本阶段不训练端到端医学报告生成模型，也不复现完整 report generation 论文。

v0.6.0 重点是基于现有模块生成完整 case artifact：

- DR 分级预测
- 置信度输出
- CAM 可解释性图
- 结构化视觉线索 findings
- 病例分析报告草稿
- Markdown / HTML 展示结果

目标输出不是临床诊断报告，而是用于科研展示、导师沟通和医院需求对接的 case analysis report draft。

## 3. 技术路线选择

当前 APTOS2019 数据集只有眼底图像和 DR 分级标签，不包含真实医生报告文本。

因此，v0.6.0 暂不采用端到端 image-to-report generation 路线。

端到端医学报告生成通常需要：

- 图像-报告配对数据
- 大量真实医学文本报告
- 报告级 ground truth
- 医生质量评估
- BLEU / ROUGE / CIDEr / RadGraph / clinical correctness 等评估指标

当前项目暂不具备这些条件。

v0.6.0 采用 structured evidence-to-report drafting 路线：

1. 视觉模型输出 DR 分级预测
2. CAM 模块输出视觉关注区域
3. findings 模块生成结构化视觉线索
4. template 或 optional LLM 将结构化证据组织为报告草稿
5. 保存完整 case artifact

这种路线的优势是：

- 不依赖图像-报告配对数据
- 能复用现有 benchmark 和 CAM adapter
- 中间证据可追踪
- 更容易加入人工审核机制
- 更适合向医院展示和反推数据需求

## 4. 旧 demo 升级路径

`v0_2_2_vl_reasoning_demo` 已完成早期验证，v0.6.0 在此基础上做正式化升级。

| 模块 | 旧 demo | v0.6.0 |
|---|---|---|
| 模型 | ConvNeXt 固定 | 支持指定 backbone / checkpoint |
| CAM | 旧 Grad-CAM 流程 | 接入 v0.5.3 CAM adapter |
| findings | demo JSON | 标准化 findings schema |
| report | reasoning 文本 | 固定 section 的 report.md / report.html |
| 输出目录 | v0_2_2 demo 目录 | experiments/case_reports/ |
| 运行方式 | 手动多步 | 一条命令生成完整 case artifact |

v0.6.0 不重写全部旧 demo，而是将可复用模块整理为正式 pipeline。

## 5. Case Report Pipeline 设计

v0.6.0 的 pipeline 目标：

Fundus image → Prediction → CAM Evidence → Structured Findings → Report Draft → Case Artifact

第一阶段只支持单张眼底图像输入。

推荐默认样例：

- demo_samples/cmoderatedr/d9bbdc33db83.png

第一版默认使用当前稳定的 ConvNeXt-Tiny checkpoint 和 selected CAM setting。

### 5.1 完整参数命令目标

第一版先用完整参数保证可控：

python scripts/run_case_report.py --image demo_samples/cmoderatedr/d9bbdc33db83.png --config configs/vision_baseline.yaml --checkpoint experiments/aptos_convnext_tiny/lr1e-4_bs32_seed42/checkpoints/convnext_tiny_best.pth --class-to-idx experiments/aptos_convnext_tiny/lr1e-4_bs32_seed42/configs/class_to_idx.json --output experiments/case_reports/d9bbdc33db83

### 5.2 最终简化命令目标

后续封装默认配置后，目标是支持：

python scripts/run_case_report.py --image demo_samples/cmoderatedr/d9bbdc33db83.png

默认自动解析：

- config
- checkpoint
- class_to_idx
- selected CAM setting
- output case_id

### 5.3 后续扩展

后续可以扩展为：

- 多 backbone 选择
- 批量 case report generation
- LLM report generator
- RAG 知识库
- Docker demo

## 6. 输出文件结构

v0.6.0 目标输出目录：

- experiments/case_reports/d9bbdc33db83/input.png
- experiments/case_reports/d9bbdc33db83/prediction.json
- experiments/case_reports/d9bbdc33db83/cam/heatmap.png
- experiments/case_reports/d9bbdc33db83/cam/overlay.png
- experiments/case_reports/d9bbdc33db83/findings.json
- experiments/case_reports/d9bbdc33db83/report.md
- experiments/case_reports/d9bbdc33db83/report.html
- experiments/case_reports/d9bbdc33db83/metadata.json

report.md 建议包含：

- Case Overview
- Input Image
- Model Prediction
- Confidence and Uncertainty
- Visual Findings
- CAM-based Attention Observation
- Interpretation Summary
- Limitations
- Non-clinical-use Disclaimer
- Artifact Metadata

findings.json 建议包含：

- case_id
- image_path
- predicted_class
- predicted_display_name
- confidence
- topk_predictions
- visual_findings
- cam_observation
- uncertainty_notes
- limitations
- model_info
- generated_at

必须明确：

- CAM 不是病灶标注
- 模型预测不是临床诊断
- 报告是 AI 输出草稿，不是医生报告
- 当前系统未经过临床验证

## 7. 医院数据需求与后续扩展

v0.6.0 prototype 完成后，可以用于和医院或合作方沟通后续数据需求。

### 当前能展示

- DR 分级预测
- 置信度输出
- CAM 可解释性热力图
- 结构化视觉线索 findings
- 病例分析报告草稿
- 可复现 case artifact

### 当前不能声称

- 不能作为临床诊断报告
- 不能替代医生阅片
- CAM 不能作为病灶标注
- 无法评估真实报告生成质量
- 暂不支持多模态临床信息融合

### 后续需要医院支持

- 眼底图像-医生报告配对数据
- lesion-level 病灶标注
- 院内报告模板
- 术语规范
- 医生审核反馈
- 多模态临床上下文，例如 OCT / FA / 视力 / 病史信息

### 后续版本方向

- v0.6.0：Case Report Prototype
- v0.6.1：LLM Report Generator
- v0.6.2：Docker Demo
- v0.7.0：RAG / Knowledge Grounding
- v0.8.0：Hospital-facing Requirements Report

v0.6.0 不要求：

- 训练 report generation model
- 复现完整 RRG 论文
- 使用 BLEU / ROUGE / CIDEr 做报告生成评估
- 接入正式 RAG 知识库，仅完成调研和接口预留
- 支持 Docker 一键部署，Dockerfile 草案可在 v0.6.2 完成

v0.6.0 完成后，根目录 README 需要同步升级为 benchmark + case report prototype 展示结构。
