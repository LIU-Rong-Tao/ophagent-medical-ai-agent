# v0.6.6 数据泄漏审计记录

## 1. 审计范围

审计对象：

`v0.6.6_freeze / main`

本次审计对象是 v0.6.6 的“无真实标签预审风险排序”流程，重点确认：

- 排序阶段是否使用真实标签；
- 排序阶段是否使用预测是否正确、错误类型等后验字段；
- 排序阶段是否利用 `image_path` 中的类别目录；
- 后验验证脚本与预审排序脚本是否分离。

涉及脚本：

- `scripts/build_pre_review_risk_table.py`
- `scripts/compare_pre_review_ranking_baselines.py`

涉及输出：

- `experiments/summary/v0_6_6/full_test_backbones/*/pre_review_risk_table.csv`
- `experiments/summary/v0_6_6/full_test_backbones/baseline_ranking_comparison.csv`
- `experiments/summary/v0_6_6/full_test_backbones/baseline_ranking_comparison.md`
- `experiments/summary/v0_6_6/full_test_backbones/risk_coverage_curve.csv`

## 2. 审计结论

v0.6.6 的预审风险排序阶段未发现真实标签泄漏。

具体结论如下：

1. `pre_review_risk_table.csv` 中不包含显式后验字段：

   - 无 `true_label`
   - 无 `is_error`
   - 无 `correct`
   - 无 `error_type`
   - 无 `severe_underestimate`

2. `build_pre_review_risk_table.py` 中，`pre_review_risk_score` 仅由模型输出相关信号计算：

   - `confidence`
   - `top2_confidence`
   - `margin`
   - `entropy`
   - `entropy_norm`
   - `pred_grade`
   - `top2_grade`
   - `severe_prob_mass`

3. `image_path` 仅作为元信息保留，或用于生成 `case_id`，未参与：

   - `pre_review_risk_score`
   - `pre_review_risk_level`
   - `review_priority_rank`

4. 后验字段只在评估阶段使用。

   `scripts/build_pre_review_risk_table.py` 只基于模型输出生成预审排序表；`scripts/compare_pre_review_ranking_baselines.py` 在排序完成后使用真实标签或由路径推断真实标签进行后验验证，不参与预审排序生成。

## 4. 当前仍需注意的问题

本次审计只能说明 v0.6.6 的预审排序阶段未发现标签泄漏，但仍需注意：

1. 当前 APTOS 结果应标记为探索性实验，不应表述为完全确认性验证。

2. 后续不能继续根据 APTOS 测试集结果调整：

   - 风险分数公式；
   - Top-K 比例；
   - high / medium / low 阈值；
   - fusion 权重；
   - severe underestimation 定义。

3. `build_pre_review_risk_table.py` 当前排序 tie-breaker 使用：

   - `pre_review_risk_score` 降序；
   - `entropy_norm` 降序；
   - `confidence` 降序。

   其中 `confidence` 降序作为第三排序键不属于泄漏问题，但和一般 failure detection 中“低置信更可疑”的直觉不完全一致。该问题暂不修改，后续如需调整，应单独记录并重新生成相关结果。

4. 本次审计不等价于上游模型训练/测试划分无泄漏。后续如果接入 OCT 或医院数据，需要额外检查：

   - patient-level split；
   - exam-level split；
   - volume-level split；
   - slice-level leakage；
   - 是否存在同一患者或同一 OCT volume 跨 train/test。

## 5. 当前状态与后续边界

泄漏审计已通过。Failure Detection / Selective Prediction 相关指标已在 v0.6.6 freeze 中由 `scripts/compare_pre_review_ranking_baselines.py` 补齐，包括 AUROC-Error、AUPR-Error、Top-K Error Precision / Recall / Lift、Risk-Coverage 和 AURC。

v0.6.6 当前的预审风险排序流程通过了数据泄漏审计：排序阶段未使用真实标签、预测正确性、错误类型或路径类别信息；真实标签仅用于排序完成后的后验验证。

## 6. 输入顺序稳定性补充审计

在初始 shuffle input rows 测试中，六个 backbone 的 `pre_review_risk_score`、`pre_review_risk_level` 和 `risk_reasons` 均保持一致，但少量完全同分样本出现 `review_priority_rank` 相邻互换。

该问题不属于标签泄漏，也不影响样本级风险分数、风险等级或风险原因，但说明原排序规则在完全 tied samples 上存在输入顺序依赖。

随后在 `build_pre_review_risk_table.py` 的排序键末尾加入 `case_id` 升序作为确定性 tie-breaker：

- `pre_review_risk_score` 降序
- `entropy_norm` 降序
- `confidence` 降序
- `case_id` 升序

重新生成六个 backbone 的风险表后，再次进行 shuffle input rows 测试。

最终结果：

- `convnext_tiny`: score_same=True, level_same=True, reasons_same=True, rank_same=True
- `swin_tiny`: score_same=True, level_same=True, reasons_same=True, rank_same=True
- `vit_b_imagenet`: score_same=True, level_same=True, reasons_same=True, rank_same=True
- `vit_b_official_like`: score_same=True, level_same=True, reasons_same=True, rank_same=True
- `vit_l_official_like`: score_same=True, level_same=True, reasons_same=True, rank_same=True
- `retfound_official_like`: score_same=True, level_same=True, reasons_same=True, rank_same=True

结论：当前 v0.6.6 预审风险排序生成流程对输入行顺序稳定。

## 7. 后续边界

v0.6.6 不再继续基于 APTOS2019 测试集结果调整排序规则。后续 clinical residual risk、高置信错误、severe underestimation、undergrading / overgrading、clinical cost matrix 和医生定义的 dangerous misclassification 留到 v0.6.7 单独处理。
