# v0.6.3 Controlled Real LLM Provider Design

## 定位

v0.6.3 在 v0.6.2 safety regression tests 和 audit metadata 的基础上，引入 controlled real LLM provider。

本版本目标不是证明真实 LLM 可以生成临床报告，而是验证：

- 同一套 constrained prompt 是否能约束真实 LLM 输出
- RuleBasedSafetyChecker 是否能拦截真实 LLM 输出中的高风险 unsafe claim
- safety_report.json 是否能记录真实 provider 的审计元数据
- unsafe real LLM draft 是否能触发 fallback 到 deterministic template report

## 为什么现在可以接真实 LLM

v0.6.1 已完成 guarded mock LLM drafting prototype。

v0.6.2 已补齐：

- RuleBasedSafetyChecker 回归测试
- safety rule boundaries 文档
- prompt_hash
- provider_version
- checker_version
- safety_policy_version
- deterministic provider metadata

因此 v0.6.3 可以在已有 safety baseline 上接入真实 LLM，而不是直接把项目做成 API demo。

## 核心原则

- 默认仍使用 template provider
- 真实 LLM provider 必须显式启用
- API key 只能来自环境变量
- 不提交任何 API key
- 不保存敏感请求信息
- 不声称临床可用
- 不把真实 LLM 输出直接视为可信医学报告
- 真实 LLM 输出仍必须经过 RuleBasedSafetyChecker
- unsafe draft 必须 fallback 到 deterministic template report

## Provider 范围

v0.6.3 只实现一个 OpenAI-compatible provider。

优先使用 OpenAI-compatible 设计，而不是绑定单一服务商，原因是后续可以兼容：

- OpenAI API
- DeepSeek API，如果 endpoint 兼容
- 本地 OpenAI-compatible server
- 其他兼容 chat completions 接口的模型服务

## 环境变量

计划使用以下环境变量：

- OPHAGENT_LLM_API_KEY
- OPHAGENT_LLM_BASE_URL
- OPHAGENT_LLM_MODEL

可选环境变量：

- OPHAGENT_LLM_TEMPERATURE
- OPHAGENT_LLM_TOP_P
- OPHAGENT_LLM_TIMEOUT_SECONDS

## CLI 设计

`run_case_report.py` 计划支持：

- `--report-provider template`
- `--report-provider mock_llm`
- `--report-provider real_llm`

默认值仍为：

- `--report-provider template`

真实 LLM 必须显式启用：

- `--report-provider real_llm`

## safety_report.json 需要记录

真实 LLM provider 运行时，`safety_report.json` 应记录：

- provider
- provider_type
- provider_version
- real_llm_used
- model_name
- base_url_configured
- temperature
- top_p
- timeout_seconds
- prompt_hash
- prompt_length
- checker_version
- safety_policy_version
- fallback_triggered
- final selected output

不记录：

- API key
- 完整 base URL 中的敏感 token
- 用户隐私信息
- 临床身份信息

## 不做的事

v0.6.3 暂不做：

- LLM-as-judge
- 多轮对话
- streaming
- Web demo
- Docker deployment
- LoRA / SFT
- 临床报告生成
- 医学事实自动校验
- 自动图像质量判断

## 验收标准

v0.6.3 完成后，至少应满足：

- template 默认路径不变
- mock_llm 路径不变
- real_llm provider 可通过环境变量配置
- real_llm 输出会进入 RuleBasedSafetyChecker
- unsafe real_llm draft 会 fallback 到 template report
- safety_report.json 记录真实 LLM provider 审计元数据
- API key 不进入 git、不进入 safety_report.json、不进入日志

## 风险与边界

真实 LLM 输出具有不确定性，即使 temperature 较低也不保证完全复现。

因此 v0.6.3 的重点不是追求生成质量，而是验证：

- 真实 LLM 输出是否能被 constrained prompt 限制
- safety checker 能拦住哪些高风险表述
- 哪些 paraphrased unsafe claim 会漏检
- 这些漏检如何进入后续 regression tests

当前版本仍不能声称：

- 临床可用
- 医学报告生成可靠
- hallucination 已被完整解决
- LLM 输出具备医学事实正确性保证
