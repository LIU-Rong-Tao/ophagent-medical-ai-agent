# v0.6.8b 研究备忘：Robustness and Mechanism Audit

## 这版解决的问题

v0.6.8b 用来检查 v0.6.8 learned deferral score 的稳健性和机制边界。

核心问题不是继续提高 learned_logistic，而是判断：

1. learned_logistic 是否稳定超过最强 simple rule；
2. learned_logistic 和 simple rule 捕获的危险样本是否高度重叠；
3. learned_logistic 主要依赖哪些风险信号；
4. 换不同 grouped CV seed 后结论是否稳定。

## 口径修正记录

早期曾测试过 pooled-ranking bootstrap 实现，但该实现与 v0.6.8 预设的 per-backbone reporting endpoint 不一致，因此不纳入正式结果。

正式结果使用 per-backbone aggregate endpoint：

- 每次从 `image_key` 层面有放回抽样；
- 每个 backbone 内部分别取 Top20%；
- 再聚合 captured、total、residual；
- 在同一个 bootstrap replicate 内比较 learned_logistic 和 simple rule。

权重版 bootstrap 已与暴力复制版 bootstrap 做等价性验证，主要差异项均为 0。

## 当前判断

v0.6.8b 的结果说明：

- learned_logistic 有竞争力；
- learned_logistic 能超过早期 `ophagent_combined`；
- learned_logistic 没有稳定超过 `expected_gap_only` 或 `gated_severe_prob_mass_only`；
- 系数分析显示它主要在重加权已有 severity-aware signal。

因此，当前不应继续堆 XGBoost、MLP 或强化学习模型。

## 后续决策

下一步应该从方法开发转向协议冻结和外部验证前检查。

建议顺序：

1. 冻结 primary targets：`large_undergrading`、`vision_threatening_dr_miss`；
2. 冻结 Top20% 作为主复核预算，同时保留 Top10% / Top30% 作为补充；
3. 冻结事件特异性主信号：
   - `large_undergrading`：`expected_gap_only`
   - `vision_threatening_dr_miss`：`gated_severe_prob_mass_only`
4. 保留 `learned_logistic` 作为监督式复核排序基线；
5. 进入 IDRiD / MESSIDOR2 外部 DR 验证前检查。
