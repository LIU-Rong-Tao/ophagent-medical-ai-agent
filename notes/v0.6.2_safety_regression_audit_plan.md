# v0.6.2 Safety Regression and Audit Metadata Plan

## 定位

v0.6.2 不急于接入真实 LLM API，而是先补齐 v0.6.1 guarded generation 链路中最容易被质疑的部分：

- safety checker regression tests
- prompt hash
- provider version
- checker version
- deterministic metadata
- safety_report schema sanity check

目标是让 v0.6.1 的 rule-based guard 从“能跑通 mock case”升级为“有回归测试和审计元数据支撑的 safety guard baseline”。

## 为什么不直接接真实 LLM

真实 LLM 会引入输出随机性、成本、provider 差异和更多同义越权表达。

在没有 regression tests 和 audit metadata 前直接接真实 LLM，容易让项目变成 API demo，而不是可控的 guarded generation workflow。

因此 v0.6.2 先固定 safety baseline，v0.6.3 再接 controlled real LLM provider。

## 优先任务

### 1. Safety checker regression tests

新增 pytest 测试，覆盖：

- safe draft should pass
- unsafe diagnosis should fail
- unsafe CAM overclaim should fail
- unsafe mixed draft should fail
- missing non-clinical-use statement should fail
- missing human-review statement should fail
- image-quality overclaim should fail
- clinical-use overclaim should fail
- representative paraphrased unsafe claims should fail

### 2. Audit metadata

在 safety_report.json 中增加：

- prompt_hash
- provider_version
- checker_version
- deterministic_provider
- generated_at
- safety_policy_version

### 3. Safety report sanity check

增加最小 schema sanity check，确认 safety_report.json 至少包含：

- provider
- prompt_length
- prompt_hash
- overall_pass
- fallback_triggered
- flagged_claims
- selected_output
- artifact_policy

## 暂不做

v0.6.2 暂不做：

- OpenAI / Claude / local real LLM provider
- LLM-as-judge
- Web demo
- Docker deployment
- LoRA / SFT
- 临床报告生成

## 阶段性验收

v0.6.2 完成后，应能说明：

- RuleBasedSafetyChecker 有固定 regression tests
- 常见 unsafe claim 变体不会无声漏掉
- safety_report.json 不只记录 pass/fail，也记录 prompt/provider/checker 元数据
- 后续真实 LLM provider 接入前，基础 safety baseline 已经可回归验证
