# v0.7.0 Checkpoint 与 RETFound Protocol 审计

## 版本定位

v0.7.1 计划使用 APTOS frozen checkpoints 在 IDRiD / MESSIDOR2 上进行 direct external validation。

进入外部验证前，需要记录各 checkpoint 的来源、训练协议和解释边界，尤其是 RETFound-related checkpoint。

## RETFound-related checkpoint 的准确表述

当前 OphAgent 中的 RETFound-related backbone 应表述为：

> RETFound-MAE-CFP initialized ViT-L under the OphAgent official-like unified training protocol.

不应表述为：

> strict official RETFound fine-tuning reproduction.

## 已对齐的部分

当前 RETFound-related setting 已对齐或接近官方设置的部分包括：

- RETFound MAE CFP checkpoint；
- ViT-L/16；
- 224 输入；
- 50 epochs；
- `blr=5e-3`；
- `min_lr=1e-6`；
- warmup 10；
- `weight_decay=0.05`；
- label smoothing 0.1；
- `drop_path=0.2`。

仓库后续补充了 ViT-L official-like baseline，因此 backbone scale 已经与 RETFound-related provider 对齐。

## 未严格对齐的部分

当前实现仍不能称为 strict official RETFound fine-tuning reproduction，主要差异包括：

- 官方 `layer_decay=0.65` 未严格复用，当前训练使用 OphAgent 统一 AdamW 设置；
- 官方 `global_pool=True` 路径未明确复用，当前 timm ViT 默认更接近 CLS-token pooling；
- 官方参数分组与 no-weight-decay 处理未严格复用；
- 官方 RandAugment、RandomResizedCrop、random erasing、bicubic eval crop 未严格复用；
- 官方 checkpoint key 检查和 head 初始化流程未严格复用；
- `interpolate_pos_embed` 未使用，不过同为 224 输入时影响通常有限。

## 对科研解释的影响

该差异不阻塞 OphAgent 的审计主线。

OphAgent 的核心问题不是复现 RETFound 官方最优性能，而是：

> 冻结模型和审计协议后，事件特异性风险信号能否在外部 DR 数据上富集危险低估，并量化未进入优先复核区残余风险。

因此，RETFound-related checkpoint 在本项目中只是六个 frozen model output providers 之一。

后续不得：

- 根据该 checkpoint 评价官方 RETFound 方法本身优劣；
- 把外部结果包装成官方 RETFound 复现；
- 把分类器迁移失败归因于 RETFound 官方 protocol 失败。

## v0.7.1 报告要求

v0.7.1 必须分开报告：

1. frozen checkpoint classification transfer performance；
2. review prioritization performance；
3. checkpoint implementation boundary。

外部分类性能无论好坏都要报告。

如果分类迁移严重崩溃，审计排序结果只能作为 failure analysis，不能强称 OphAgent protocol 泛化成功。

## 后续可选补充实验

如果后续需要专门讨论 foundation model 本身，可以另开补充实验：

- 使用官方 RETFound repo；
- 严格复用官方 fine-tuning 参数；
- 重新训练 APTOS checkpoint；
- 再做 IDRiD / MESSIDOR2 external validation；
- 与当前 OphAgent unified-protocol checkpoint 分开报告。

该补充实验不是 v0.7.0 的必要前置条件。
